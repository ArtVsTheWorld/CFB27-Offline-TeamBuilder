# October 30 native update

The previous profile is kept for regression tests. The new profile is embedded
in version 2.1.4; the runtime never selects a profile by EXE hash.

The native targets were mapped from the previous decoded executable to a
read-only capture of the updated game. Function signatures were normalized
only for branch displacements and RIP references. Referenced globals and
tables were matched through decoded callers and pointer sequences.

All 60 named symbols were resolved. The ten TeamBuilder lifecycle slots kept
their positions. The three transport hooks were checked separately: the older
profile's nominal RVAs were historical hints, while the engine resolved their
real locations at runtime. The new profile uses their current locations. The
ProtoHttp wrapper was selected through the actual MCR request caller, not
through its shared prologue alone.

The decoded-team function has a changed stock tail dispatch slot, from +0x4B0
to +0x4B8. The plugin leaves that stock tail in place. Its entry ABI, overwritten
prologue and audio handoff contract remain unchanged.

The relay instruction templates and relocation definitions are unchanged.
Golden tests undo only the address changes before checking the original hashes.
Private native fixtures execute against the new profile's symbols.

The fbmod uses game head 0x42336A and the current three collector GUIDs. All six
collector/movie baseline comparisons had identical APT data and constant
streams. Manifest and embedded payload bytes are preserved. Superbundle names
also match. The editable project was exported from that rebased mod and checked
through EOF against the SDK-decoded payloads.

Validation: 4,309 local runtime checks, 21 packaging checks, six repository-check
tests, and 40 read-only live native checks passed. Those live checks included
both capacity bindings, the capacity accessor and the initialized singleton.
The user subsequently confirmed version 2.1.4 works in-game on October 30, 2026.
